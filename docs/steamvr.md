# SteamVR 悬浮面板

预装服务组件 `yanuo.steamvr` 是显示方：它连接 SteamVR，把面板目录里打开着的面板各显示成一块 SteamVR 的悬浮窗口(overlay)，画面来自核心离屏渲染的面板页面；面板留在空间里，或者附着在头显、左手、右手的手柄上跟着走(附着在手上的可以只在抬手看它时显示)；用手柄指、点、抓住移动、双手缩放，用手柄键整组收起和恢复、开关快捷位的面板；提供远程服务 `panels`。这篇讲文件分工、哪些面板显示、附着的面板、连接、每帧循环、渲染、手柄交互、出错时怎么办、布局和设置、按键绑定、模拟模式。

## 组成

| 部分 | 位置 | 做什么 |
|---|---|---|
| SteamVR 组件 | `components/steamvr/` | `kind: service`，提供 `panels`，`process: own`(独占一个组件进程，见 [组件进程](component-process.md))。连接、面板、指针、手柄、状态栏都在这里 |
| 面板页面 | `src/main/panels.ts` | 核心在 Electron 主进程里离屏渲染面板页面，把每一帧的共享纹理交给显示方；组件经 `ctx.panels` 用它(接口见 [SDK](sdk.md#显示方ctxpanels-和远程服务-panels)) |
| 面板布局 | `components/_shared/panels/layout.ts`、`calls.ts` | 各显示方共用：布局的状态机(每块面板打开没有、常显、锁、宽度、附着在哪、抬手才显示、位置，总开关收起的那一组，同时显示的上限，出错停用)，显示方设置的收窄，合成远程服务 `panels` 的状态；`calls.ts` 把远程调用的参数收窄成命令再作用到布局上。全是纯函数 |
| OpenVR 库 | `vendor/openvr/openvr_api.dll` | 组件用 koffi 调它的 C 接口，路径由 `ctx.appDir` 拼出 |
| SteamVR 资源 | `resources/vr/` | 应用清单、动作清单、三种手柄的默认绑定、指针贴图 |

| `components/steamvr/src/geometry.ts` | 3×4 矩阵运算，射线和面板求交(`rayQuad`、`nearestHit`)，摆放(`arrange`、`needsArrange`)，附着(`relativeTo`、`anchorPose`、默认的相对位置 `anchorDefault`、抬手才显示的判断 `glanceShown`)，松手摆正(`settlePose`)，平滑，圆点的位置。纯函数；附着和抬手才显示的距离、角度在文件顶部，其余的初值在各节开头 |

| `components/steamvr/src/api.ts` | 组件用到的原生能力的接口：`Vr`(悬浮窗口的绝对位置 `place` 和跟着设备 `placeOn`、姿态、输入、应用登记)、`Gpu`(共享纹理复制到常驻纹理)，建一次连接用的 `VrBackend`，显卡设备丢了的错误 `GpuLost` |
| `components/steamvr/src/openvr.ts` | `OpenVR`：`Vr` 的原生实现，OpenVR C 接口的绑定，只封装用到的方法。手写的函数原型集中在 `PROTOS`(函数表里的方法)和 `ENTRY_PROTOS`(DLL 的入口函数)，头文件里的常量都导出；构造函数收五个接口的函数表(`VrTables`)，`OpenVR.connect()` 传的是原生的 |
| `components/steamvr/src/d3d.ts` | `D3D`：`Gpu` 的原生实现，D3D11 建设备、打开共享纹理、复制到常驻纹理；`readback` 把纹理读回内存，只有模拟模式用 |
| `components/steamvr/src/fake.ts` | `FakeVr`、`FakeGpu`：不碰原生库的 `Vr` 和 `Gpu`，每次调用都记下来，姿态、按键、求交结果、哪个方法出错由外面给。测试和模拟模式用它 |
| `components/steamvr/src/ffi.ts` | koffi 的公共部分：DLL 句柄、命名类型 |
| `components/steamvr/src/fntables.ts`、`components/steamvr/src/d3d-vtables.ts` | OpenVR 函数表和 D3D 虚表的方法顺序，由 `scripts/gen-openvr.ts`(读 `vendor/openvr/openvr_capi.h`)和 `scripts/gen-d3d.ts`(读 Windows SDK 头文件)生成 |

## 显示哪些面板

面板目录(`ctx.panels.list`，开着的组件声明的面板，按组件顺序)里的每块面板在布局里有一条记录：打开着没有、常显、锁定、宽度、附着在哪、抬手才显示、位置。规则都在共用的状态机里(`components/_shared/panels/layout.ts`)，开发用的显示方用的是同一份：

- **进目录就算打开**。显示方第一次见到一块面板，或者它的组件关掉后又打开，这块面板算打开着。想让一块面板不出现，就在主窗口的组件页关掉它的组件。面板用自己的收起按钮(`ctx.panel.hide()`，走的是 `open(id, false)`)收起后算关着，位置、大小留着：按总开关显示面板时它一起回来；它的组件关掉再打开时也重新出现。位置、大小、常显、锁的记录在组件关着时留着，组件卸载完(`core/component-removed`)才删。
- **总开关**。启动时、SteamVR 断开时算「总开关收起着」：打开着的非常显面板都在收起的那一组里，不显示。总开关键(或 `toggleAll`)：有面板藏着就全部显示；否则把显示着的非常显面板整组收起；两样都没有时什么都不做(出错停用的面板重试)。「藏着」是收起的那一组里有面板，或者目录里有关着的面板(用自己的收起按钮、快捷位键、`open(id, false)` 关掉的；有没有快捷位指向它都算)。「全部显示」是恢复那一组、把关着的面板都打开、出错停用的重试，之后不算收起着；打开着的多过上限时照上限的规则显示：快捷位指向的面板占着位置，其余的只显示目录里靠前的(见下面的上限)。出错停用的面板(没被关掉、只是停用着)不算藏着：别的面板显示着时按总开关键照样整组收起，它在全部显示时、没有面板可显示可收起时按总开关键才重试。所以只关了一块、别的还显示着时，按一下总开关键是那一块回来，再按一下才整组收起；SteamVR 断开再连上之后按总开关键也是同一条规则。收起着时进目录的面板进那一组，没收起着时进目录的面板直接显示。关掉一块面板不改收起着没有；单独打开一块之后那一组空了，就不算收起着。
- **常显**的面板(`set(id, { pinned: true })`)总开关不收起它，打开着时连上就显示。用收起按钮关掉的常显面板照样算藏着，按总开关键时一起回来。
- **快捷位**。设置里的两个快捷位各指向一块面板(1 号默认是预装的键盘面板 `yanuo.shell-classic`，2 号默认空)。快捷位键开关那一块，不动别的：显示着就关掉，否则打开(总开关收起着时这一块单独显示)。空位、那块面板不在目录里时什么都不做。用快捷位键关掉的面板算关着，按总开关键显示面板时一起回来。
- **同时显示的上限**(设置 `limit`，默认 8)。打开着、没被收起的面板多过上限时，快捷位指向的面板占着位置，其余的只显示目录里靠前的；排在后面的照样算打开着，前面的关掉后补上。显示着的已到上限时再打开一块不生效，快捷位指向的面板除外。
- **出错停用**的面板算关着、状态里带原因，不进存盘(见「出错时」)。

该显示的面板 = 在目录里、打开着、没被总开关收起、没出错停用、没超过上限(`shownSet`)。留在空间里的面板该显示就显示；附着在头显或手柄上的还要那个设备在，抬手才显示的还要正面朝向眼睛(见下一节)。

## 附着的面板

布局里每块面板记着附着在哪(`anchor`)：

| `anchor` | 面板在哪 | 布局里的 `pose` |
|---|---|---|
| `world` | 留在空间里 | 站立空间里的姿态 |
| `head` | 跟着头显(0 号设备) | 相对头显的变换 |
| `left` / `right` | 跟着左手 / 右手的手柄(设备序号每帧按手的角色取) | 相对手柄的变换 |

面板第一次进布局时取清单的 `panel.anchor`、`panel.glance`，清单写 `left` / `right` 的一开始锁着；之后以布局为准，经远程服务 `panels` 的 `set` 改、`reset` 回清单的值(见 [SDK](sdk.md#显示方ctxpanels-和远程服务-panels))。总开关、常显、上限、快捷位对附着的面板和别的面板一样；`summon`、显示时的摆放(`recenter`)只管留在空间里的面板，摆放时要避开的也只有留在空间里的面板。

**位置**。`pose` 为空(没摆过、换了附着对象、`reset` 之后)时用那个设备的默认位置，不记进布局；抓着挪过、松手时才记下相对变换。默认位置(`anchorDefault`，设备自己的坐标：前方 −Z，上方 +Y，右方 +X)：

- 头显：前方 0.45 米、下方 0.25 米，正面朝向眼睛。
- 手柄：朝手背一侧 0.05 米(左手柄的 −X、右手柄的 +X)、朝手腕一侧(+Z)0.12 米，正面从朝手背转向手柄上方 40°，抬手看表时朝向眼睛。

**跟随**(设置 `attach`)：

- `native`(默认)：用 `SetOverlayTransformTrackedDeviceRelative` 把相对变换交给 SteamVR，由它带着悬浮窗口走；设备序号或相对变换变了才再调。
- `js`：每帧用「设备的姿态 × 相对变换」算出站立空间里的姿态，调 `SetOverlayTransformAbsolute`(姿态没变时不调)。面板跟不上、位置不对时换成它排查。

两种方式下组件每帧都自己算一份「设备的姿态 × 相对变换」(设备的姿态是这一帧取到的，不带预测)：求交、圆点、挡游戏按键一律用这份，不问 SteamVR。

**设备不在**。头显或手柄的姿态无效、这只手没有设备时，附着在它上面的面板隐藏，状态里 `visible` 为假；设备回来就显示，相对变换不用再告诉 SteamVR(设备序号换了才再说)。

**抬手才显示**(`glance`，只对附着在手上的面板起作用)。面板正面的法线和「面板指向眼睛」的方向夹角小于 40° 时显示出来，大于 50° 时隐藏，两者之间保持原样(`glanceShown`)。手柄不在、头显的姿态无效的那几帧不重算，照最近一次的结果：手柄丢一帧姿态再回来，回差里显示着的面板照样显示。断开重连、换了附着对象后从「没抬手」算起。

**没在显示时页面照常画**。附着的面板该显示而设备不在、没抬手时，悬浮窗口隐藏着待命：页面不停画(页面里的 `ctx.panel.visible` 为真)，帧照常复制进纹理，画面变了就交给 SteamVR，抬手的那一刻显示的就是最新的画面。这样的面板不算进 60 秒关页面；被总开关收起、关掉后才停画、才开始计时。状态里它的 `visible` 为假，状态栏的面板数不算它。

对一块附着的悬浮窗口的原生调用：

| 情况 | 调用 |
|---|---|
| 第一次显示 | `SetOverlayWidthInMeters` → `SetOverlayTransformTrackedDeviceRelative` → `ShowOverlay` |
| 没显示过(设备不在、没抬手) | 建好、设宽度，不调放位置的；第一次显示时才调 |
| 设备回来、抬手 | `ShowOverlay`；设备序号换了的在它前面多一次 `SetOverlayTransformTrackedDeviceRelative` |
| 留在空间里 → 附着、换附着对象 | 只多一次 `SetOverlayTransformTrackedDeviceRelative`，不隐藏 |
| 附着 → 留在空间里 | 只多一次 `SetOverlayTransformAbsolute` |
| 抓着挪 | 每帧一次放位置的调用(`native` 是相对设备的，`js` 是绝对位置的) |

留在空间里的面板的调用和有没有附着的面板无关：`test/vr-world-calls.test.ts` 把一遍常用操作里对 SteamVR 和显卡的每一次调用和记下来的那份(`test/vr-world-calls.json`)逐条比对。

下面这些数值是初值，要戴着头显看效果来调，都在 `components/steamvr/src/geometry.ts` 顶部：`HEAD_AHEAD`(0.45 米)、`HEAD_BELOW`(0.25 米)、`HAND_BACK`(0.05 米)、`HAND_WRIST`(0.12 米)、`HAND_TILT`(40°)、`GLANCE_ENTER`(40°)、`GLANCE_LEAVE`(50°)。手柄上的默认位置是按手柄姿态的坐标轴(手背在左手柄的 −X、右手柄的 +X，手腕在 +Z)推出来的。默认位置不记进布局，改了数值重新构建后，没摆过的面板用的就是新值。

## 连接和断开

### 生效和等着

远程服务 `panels` 的同名提供者里只有组件顺序最前的开着的那个生效(见 [组件进程](component-process.md#远程服务))，只有它开得了面板页面。组件从 `ctx.relay.serve('panels', …)` 返回的把手上看自己生效没有(`active`、`watch`)：

- **等着**(带 `FOXPANEL_PANELS=1` 启动时开发用的显示方排在前面，就是这样)：不探测、不连 SteamVR，不开面板页面，不建悬浮窗口，不读手柄。状态栏是灰灯，它发布的状态里 `connected` 为假。运行日志里有一行警告说明 `panels` 由谁提供。
- **变成生效**：开始探测和连接，连上后照布局显示。
- **变回等着**：停止探测，断开 SteamVR(收尾和下面「断开时」一样)，开着的面板页面全部关掉，写了 `keep` 的也关——页面归生效的显示方开。再生效时重新连上，这时面板在收起的那一组里：常显的直接显示，其余的按总开关键恢复(关着的面板也一起回来)。

### 连接

组件加载后读回存着的布局(同一个进程里重新加载时接着用留下的那份，见「布局和设置」)，登记远程服务 `panels`；登记生效着就开始探测。开始时探测一次，之后每 5 秒一次，没连着时才探测：

1. `VR_IsRuntimeInstalled` 为假 → 没装 SteamVR，不连。
2. 以后台应用类型(`VRApplication_Background`)试着初始化：这种类型不会启动 SteamVR，SteamVR 没在运行时初始化失败 → 不连。成功就立即结束这次初始化。
3. 以悬浮窗口应用类型(`VRApplication_Overlay`)正式连接，取 `IVRSystem_026`、`IVROverlay_028`、`IVRInput_011`、`IVRApplications_008`、`IVRRenderModels_006` 五个接口的函数表。

连上后依次做：

- 在头显所在的显卡上建 D3D11 设备(显卡的 LUID 来自 `IVRSystem::GetOutputDevice`；取不到时用默认显卡)。
- 应用键 `yanuo.foxpanel` 没在 SteamVR 里登记过时，登记应用清单并设为随 SteamVR 启动。清单有两份，启动命令是相对清单文件写的：源码运行(可执行文件在程序目录里的 `node_modules` 下)登记 `resources/vr/manifest.vrmanifest`，安装版(可执行文件在程序目录外面)登记 `resources/vr/manifest.packed.vrmanifest`(`appManifestName`，在 `src/main.ts`)。登记失败只记一条警告。应用键登记过就不动它：登记时的位置和这次运行的不一样时(换过安装目录，或源码版和安装版都在这台机器上跑过)，SteamVR 里留的是登记时的那个位置。
- 设置动作清单 `resources/vr/actions.json`，取动作集和五个动作的句柄。
- 给左右手各建一个指针圆点。
- 开每帧循环：频率是头显刷新率，限制在 30–144 Hz(读不到刷新率时按 90 Hz)。

面板的悬浮窗口不在连接时建：每帧循环照布局建(见下)。出错停用的面板在连上时清掉原因重试。

断开的情况：

| 情况 | 处理 |
|---|---|
| 收到 SteamVR 的退出事件(`VREvent_Quit`) | 断开 |
| 取事件、取姿态、更新动作集、读按键抛出异常 | 记错误日志，断开 |
| 显卡设备丢了(`GpuLost`：驱动重置、显卡被移除) | 记错误日志，断开；重新连上时建新的设备 |
| 组件停用或卸载、登记变回等着 | 停止探测，断开 |

断开时：按着的扳机替页面补抬起、指着的面板发移出(页面留着，按住连发的键靠这两样停下)；销毁两个圆点和各块面板的悬浮窗口、放掉纹理和 D3D 设备、结束 OpenVR 会话；面板的页面不关，只停画；显示着的非常显面板并进收起的那一组，布局算收起着。探测一直在跑，SteamVR 重新启动后 5 秒内自动连上，接着用同一批页面：常显的面板连上就重新建悬浮窗口，其余的按总开关键恢复(断开之前关掉的面板也一起回来)，位置和宽度是布局里的，输入框里没发出去的字还在。断开着时，页面没了的、不显示满 60 秒且清单没写 `keep` 的面板，在探测时关掉页面。连接失败时放掉连到一半的资源；同一个错误连续出现只记一次日志。组件停用或它的进程退出时，页面由核心保留 120 秒(见 [组件进程](component-process.md#面板页面))。

SteamVR 里用到的悬浮窗口键：

| 键 | 是什么 |
|---|---|
| `yanuo.foxpanel:panel.<面板 id>` | 一块面板(名字 `FoxPanel <面板 id>`)。超过 100 个字符时截断，末尾换成面板 id 的 SHA-256 的前 8 位(SteamVR 的上限是 128) |
| `yanuo.foxpanel:pointer.left` / `pointer.right` | 左右手的指针圆点 |

建悬浮窗口时 SteamVR 报键已占用：这个键是这次连接里自己建过、销毁没成的，就用 `FindOverlay` 找到那一个接着用，并把它隐藏；是别的程序占着的(比如同时开着的另一个 FoxPanel)，照常报错，不碰那个悬浮窗口——圆点的键被占着时连接失败，面板的键被占着时算那块面板出错。

状态栏：组件上报一项 `STEAMVR`，连上是绿灯、后面是显示着的面板数(附着的面板里设备不在、没抬手的不算)，没连、等着是灰灯(状态栏见 [主窗口](main-window.md))。运行日志里连接和断开各有一行 `steamvr connected` / `steamvr disconnected`。

## 每帧循环

每个显示帧(`Session.tick`)按这个顺序：

1. 取 SteamVR 事件；有退出事件就断开。
2. 取所有设备的姿态(站立空间)：头显、两只手柄和它们的指尖。
3. 面板表照布局对一遍(`Stage.reconcile`，带上头显和两只手柄这一帧的姿态)，给出这一帧显示着的面板。
4. 两只手的射线对每块显示着的面板求交；附着在一只手上的面板不和这只手求交。
5. 更新动作集：要挡游戏按键时用最高优先级，否则 0。
6. 读两只手的按键，拼成这一帧的输入。
7. `interact.step` 算出指令。
8. 执行指令：圆点自己放，总开关和快捷位交给布局，其余的交给面板表。
9. 逐块把纹理交给 SteamVR(`Stage.submit`)。
10. 布局有改动时发布一次 `panels` 的状态(一帧里的改动合成一次)。

远程服务 `panels` 的调用在连着时下一帧才见效；没连着时当场发布。

### 面板表照布局对一遍

- 不在目录里的面板：销毁悬浮窗口、关掉页面。
- 该显示的面板：没有页面就开(`ctx.panels.open(面板 id, 'frames')`，开的时候停着画)，没有悬浮窗口就建(隐藏着)；宽度和位置跟上布局；没显示的显示出来，页面开始画。
- 该显示的附着的面板：宽度跟上布局，页面画着；设备在、(抬手才显示的)正面朝向眼睛时跟上设备并显示出来，否则隐藏着待命(见「附着的面板」)。布局里的附着对象变了，下一帧照新的对象重新放。
- 不该显示的面板：显示着的隐藏(没成功的下一帧接着试)，页面停画；隐藏满 60 秒(`PAGE_LINGER_MS`)且清单没写 `keep` 的，销毁悬浮窗口、关掉页面，再显示时重新开。
- 清单写了 `keep`、打开着的面板(被总开关收起着、排在上限之后)：页面在连着时就开着停画，悬浮窗口到显示时才建，显示出来不用等页面加载。预装的键盘面板是这样。别的面板从没显示过时不开页面、不建悬浮窗口。
- 一帧里最多建或销毁一个悬浮窗口(`OVERLAYS_PER_FRAME`)，多的排到后面的帧。页面没了(`gone`)时也只摘掉页面，悬浮窗口留到这里按名额销毁。

显示时的摆放(设置 `recenter`，只管留在空间里的面板)：面板由不显示变成显示时(总开关恢复、快捷位键、`open`、重连后重建都算)，

- 还没摆过的(布局里没有位置)：放到面前；
- `never`：留在上次的位置；
- `away`(默认)：不在面前才放回面前——离眼睛不到 0.2 米或超过 1.5 米，或方向偏离视线超过 50°，或正面没朝着人；
- `always`：每次都放回面前。

放到面前(`arrange`)按清单的 `spawn`，以头的水平朝向为准，正面朝向眼睛、不侧倾：

| `spawn` | 离眼睛(水平) | 比眼睛低 | 方向 |
|---|---|---|---|
| `front` | 0.65 米 | 0.05 米 | 正前方 |
| `low` | 0.55 米 | 0.3 米 | 正前方 |
| `side` | 0.65 米 | 0.05 米 | 向右 35° |

出现位置 0.2 米以内已有别的显示着的、留在空间里的面板时，依次试再向右 35°、向左 35°、向右 70°、向左 70°；都占了就在第一个方向上朝头每块错开 0.05 米，最近到离眼睛 0.2 米。摆好的位置记进布局。`summon` 和 `reset` 做的就是忘掉位置，下一帧在这里重新放(附着的面板 `reset` 后回到设备上的默认位置)。

## 面板的渲染

面板页面在主进程里离屏渲染成 GPU 共享纹理，组件进程把它复制到自己的常驻纹理，再交给 SteamVR。画面全程在显存里，不经过内存。

### 核心：面板页面

核心(`src/main/panels.ts`)为显示方开一个隐藏的离屏窗口加载这块面板的页面 `fox://<面板 id>.panel/panel.html`，大小是清单的页面宽高，纹理像素 = 页面像素 × 清单的纹理倍数。每画出一帧，核心把共享纹理的 NT 句柄复制进组件进程，交来 `{ seq, handle, width, height }`；组件用完后关掉句柄并 `release(seq)`，核心才放掉这一帧。核心替一页最多压 4 帧，再来一帧时放掉最早的并通知组件(`onDrop`)：组件手里还留着的关掉句柄，不用它也不还。

开页面、帧的交接、指点事件、停画、保留期的完整规则和消息见 [组件进程](component-process.md#面板页面)。

### 组件：复制和提交

`Surface` 只留最新的一帧，旧的没用上就还给核心；常驻纹理按帧的实际宽高建。不显示时不留帧：页面交来的帧直接关句柄还回去，隐藏时手里的帧都还回去；待命的悬浮窗口(附着的面板该显示而设备不在、没抬手)不显示也照常收帧、复制，纹理只在画面变了时交。悬浮窗口销毁(断开、面板关掉)时把页面摘掉，手里的帧还回去。每个显示帧对每块面板各调一次 `submit()`(不显示也不待命的只收掉做到一半的复制)：

1. 上一次复制 GPU 还没做完 → 这一帧什么都不做。
2. 有新帧 → 还掉手里的那一帧，把新帧复制到常驻纹理。
3. 没有新帧、手里的帧只复制过一次、且离上次复制完成满 30 毫秒 → 同一帧复制第二次。新帧到达时 Chromium 可能还没画完，只复制一次的话静止的画面会停在旧内容上。
4. 手里的帧已经复制过两次 → 还给核心。
5. 常驻纹理里有完整的一帧、且没有复制在进行 → `SetOverlayTexture` 交给 SteamVR。设置 `textureSubmit` 是 `always`(默认)时每个显示帧都交；是 `changed` 时只在一次复制完成后、悬浮窗口刚显示出来时交一次。

还一帧 = 关掉自己进程里的句柄(`CloseHandle`)，再调 `release(seq)`。

宽度(`SetOverlayWidthInMeters`)、位置(留在空间里的 `SetOverlayTransformAbsolute`，跟着设备的 `SetOverlayTransformTrackedDeviceRelative`)、显示和隐藏只在和记着的值不同的时候调；显示着没有、位置不向 SteamVR 问。

复制的做法(`components/steamvr/src/d3d.ts`)：

- 常驻纹理是 BGRA8、和帧同尺寸的 `ID3D11Texture2D`；帧的尺寸变了就重建(新纹理建不出来时不留着放掉的那张和它的尺寸，下一帧重新建)。
- `ID3D11Device1::OpenSharedResource1` 打开共享纹理，`CopyResource` 整张复制，随后在一个事件查询上 `End` 并 `Flush`。
- 不阻塞等 GPU：每帧用 `GetData`(`DONOTFLUSH`)看查询是否完成，完成后才释放源纹理。组件进程的主线程要跑手柄循环，不能停下来等。
- 建对象、打开共享纹理、查进度返回设备丢了的 HRESULT(`DXGI_ERROR_DEVICE_REMOVED`、`DEVICE_HUNG`、`DEVICE_RESET`、`DRIVER_INTERNAL_ERROR`)时抛出 `GpuLost`。

### 重新加载

组件在同一个进程里会被卸载再加载(改了它的设置就是这样生效的)。koffi 的命名类型(结构体、函数原型)整个进程共用，`components/steamvr/src/ffi.ts` 定义类型时同名的已经在了就取已有的；加载过的 DLL 句柄按路径留着不放。

## 手柄

### 指尖和求交

- **指尖**：手柄模型里名叫 `tip` 的部件相对手柄的变换(`IVRRenderModels::GetComponentStateForDevicePath`)，乘上手柄的姿态得到指尖在世界里的位置。手柄的设备序号变了就重新取；取不到时每 1 秒重试。没有设备、姿态无效、取不到指尖的手不算指着任何面板。附着在手上的面板跟的是手柄的姿态，不是指尖的。
- **射线**：从指尖出发，沿指尖的 −Z 方向。
- **求交在 JS 里算**(`rayQuad`)：悬浮窗口是以变换原点为中心的矩形，宽沿 +X，高 = 宽 × 纹理的高 / 宽、沿 +Y，正面朝 +Z。给出落点的纹理像素(原点在左上角；交点在面板外时夹到最近的边上)、在不在面板里、是不是从正面打过来、交点、距离。一只手指着的是从正面打在面板里的那些里最近的一块(`nearestHit`)。附着在一只手上的面板不吃这只手的射线(`reaches`)：没有事件、没有圆点、不挡游戏按键，另一只手照常指和点；附着在头显上的面板两只手都能指。宽高用常驻纹理的，还没有纹理时用页面报的。SteamVR 自己的求交(`ComputeOverlayIntersection`)把命中区域按边长等于宽度的正方形算、不分正反面、`v` 自下而上，竖长的面板上下两端点不到，所以不用它当主路径。
- 两条退路(组件的设置)：`hitTest: native` 整体改用 SteamVR 的求交(结果经 `uvToPixel` 换成同样的落点，落在面板的矩形外不算)；`hitCheck` 打开时每帧对指着的那块另外问一次 SteamVR，两种算法的落点差 2 像素以上记一行警告(`hit check <面板 id>: js x,y native x,y`)，一秒最多一行。两条退路都只管留在空间里的面板，附着的面板一律用这里算出的姿态求交。
- **圆点**：直径 6 毫米的悬浮窗口，贴图是 `resources/vr/pointer.png`(128 × 128，白色实心圆加 `#4f5bd5` 描边，由 `scripts/gen-pointer.ts` 画出)。放在落点沿面板正面抬起 2 毫米处，和面板同朝向，排序(10)在面板(0)之上。指着面板的正面时显示，移开时隐藏；显示状态变了才告诉 SteamVR，没成功的下一帧重试。

### 指和点

- **一块面板只听一只手**(驱动手)：先指上来的那只。另一只手也指着它时圆点照样显示，但不给页面发事件，移开也不发移出。另一只手在它上面按下扳机时换手：前一只还按着的先替它补抬起。驱动手移开时发移出(`leave`)，面板重新等一只手指上来。
- 驱动手指着时每帧给页面发 `move`(带着扳机是否按着)。动作 `OverlayInteract`(默认扳机)按下发 `down`，松开发 `up`。没指着面板时扳机不发事件。
- **按住不丢**：扳机按住期间这只手锁在按下的那块面板上，射线滑出边缘时落点夹在边上继续发 `move`，圆点停在边上；松开时在那里发 `up`，之后才算移出。
- 面板不显示了(收起、关掉、出错)：按在它上面的扳机补 `up`，指着它的手发 `leave`。

核心把坐标从纹理像素换成页面像素，把 `move` 变成页面的 `mouseMove`(按着时带左键按下的修饰)，`down` / `up` 变成左键的 `mouseDown` / `mouseUp`，`leave` 变成 `mouseLeave`。VR 里没有滚轮：能滚动的区域靠按住拖动滚(见 [面板页面](panel-page.md#拖动滚动))。

### 抓和缩放

- **抓**：动作 `OverlayGrab`(默认握把)按下时这只手正指着一块能动的面板，按住满抓取延迟(设置 `grabDelay`，默认 0.15 秒；附着在手上的面板固定 0.4 秒，不跟设置)后面板跟手：记下面板相对指尖的位置，之后面板向「指尖 × 记下的相对位置」靠近——时间常数 0.04 秒的指数平滑，位置线性插值、旋转球面插值，只保留旋转和位置。没满延迟就松开或把射线移开，这次不算；抓起来以后射线移开也不脱手。握把按下时没指着面板：不抓，也不挡游戏。
- **松手**：面板留在原地，位置记进布局。设置 `snap` 开着时摆正(`settlePose`)：侧倾在 8° 以内归零，离竖直在 6° 以内立正，位置和朝哪个方向不变；平躺着的面板不动。附着的面板不摆正。
- **抓着附着的面板**(解了锁才抓得动)：面板跟着抓它的手走，附着的设备这期间动了不带着它晃——抓着的那几帧以上一帧给它的站立空间里的姿态为准；松手后仍附着在同一个设备上，记进布局的是相对那个设备这一刻的变换。抓着它的手姿态无效的那几帧，面板照最近的相对变换跟着设备走。
- **两只手各抓一块**：各移各的。
- **双手缩放**(设置 `stretch`)：两只手抓着同一块时，记下两手指尖的距离 `d0` 和面板宽度 `w0`，之后宽度 = `w0 × d / d0`，夹在这块面板清单的 `minMeters`–`maxMeters` 之间；两手距离不到 0.05 米时按 0.05 米算。缩放时面板跟着先抓住它的那只手。任一只手松开时结束：宽度取整到厘米(不出清单的范围)记进布局，还抓着的那只手重新记相对位置，面板不会跳。设置关着时第二只手抓不了已经被抓着的面板。附着在一只手上的面板，这只手的射线够不着它：另一只手已经抓起它时，这只手的握把按住满 0.4 秒(不用指着)就算也抓着，两手一起缩放；没按满就松开、另一只手这期间放开了都不算。
- 面板不显示了(收起、附着的设备不在、抬手才显示的转开了)就放开，不记位置和宽度；再显示时宽度和位置都是布局里的。
- **锁**：全局锁(`lockAll`)或这块面板自己的锁(`set(id, { locked: true })`)锁着时抓不动、不能缩放，点击照常。抓着时被锁上算松手。

### 挡游戏按键

设置 `blockInput` 开着(默认)时，下面任一条成立，动作集 `/actions/main` 以 SteamVR 允许的最高输入优先级(`0x01ffffff`)激活，同样的手柄按键不传给游戏；其余时候优先级是 0：

- 有手指着一块面板的正面；
- 有扳机按在面板上还没松开(滑出了边缘也算)；
- 有手抓着面板(射线移开了也算)。

## 出错时

- **只动一块面板**：它的悬浮窗口建不出来或显示不出来、纹理建不出来、共享纹理打不开、提交时抛出异常、页面出错(`failed`)。记一行警告(`panel <面板 id>: <原因>`)，这块面板歇 1 秒(`FAULT_REST_MS`：这期间不开它的页面、不动它的悬浮窗口、不交它的纹理，也指不着它)再重试。10 秒里出错 3 次就停用：销毁它的悬浮窗口、关掉它的页面，状态里 `open` 为假并带上原因(`error`)。
- 出错停用只记在内存里，布局里存的「打开着」不变：再打开这块面板(`open`、快捷位键、`summon`)、总开关显示面板(或没有面板可显示、可收起时按总开关键)、重新连上 SteamVR、组件重新加载、程序重启，都会清掉原因重试。
- **页面没了**(`gone`：被别的显示方接走、面板的组件关了)：摘掉页面，这块面板记成关着，不记错，不自己重开。面板的组件再打开时它重新算打开着；还在目录里的，按总开关显示面板时或再打开它时重新开页面。
- **断开重连**的那些情况见「连接和断开」。显卡设备丢了属于这一类：不算哪块面板出错。

## 布局和设置

### 布局

布局存在组件数据的 `layout` 键里(`ctx.storage`，见 [组件管理](component-manager.md))：

```json
{
  "locked": false,
  "panels": {
    "yanuo.shell-classic": { "open": true, "pinned": false, "locked": false, "meters": 0.9, "anchor": "world", "glance": false, "pose": [1, 0, 0, 0, 0, 0.88, 0.48, 1.3, 0, -0.48, 0.88, -0.55] },
    "yanuo.panel-wrist": { "open": true, "pinned": false, "locked": true, "meters": null, "anchor": "left", "glance": true, "pose": null }
  }
}
```

| 字段 | 含义 |
|---|---|
| `locked` | 全局锁 |
| `panels.<面板 id>.open` | 打开着(用户要它出现；被总开关收起着的也算) |
| `pinned`、`locked` | 常显、锁定 |
| `meters` | 宽度(米)；`null` = 清单的默认宽度 |
| `anchor` | 附着在哪：`world` / `head` / `left` / `right` |
| `glance` | 抬手才显示；只在附着在手上时起作用 |
| `pose` | 位置(3×4 矩阵，12 个数)：留在空间里的是站立空间里的姿态，附着的是相对那个设备的变换；`null` = 还没摆过，留在空间里的显示时按清单的 `spawn` 放，附着的用那个设备的默认位置 |

- 读回时按 `unknown` 收窄：坏的项用默认值(`anchor` 不认识或没有时是 `world`，`glance` 是假)，矩阵要 12 个有限数，id 不合格的记录丢掉。
- 总开关收起着没有、收起的那一组、出错停用的面板不存盘；每次启动总开关都收起着。
- 布局变了以后隔 500 毫秒存一次，这期间又变了就重新等；组件停用时还没存的马上存。
- 组件在同一个进程里重新加载时(改了设置)，内存里的布局连同收起的那一组留在模块里，重新加载后接着用：面板不用再按一次总开关键。
- 卸载这个组件会连布局一起删。开发用的显示方有自己的布局(只在内存里)。

### 设置

组件的设置(清单 `config`，在主窗口的组件页改；改了以后组件重新加载)：

| 键 | 默认 | 含义 |
|---|---|---|
| `quick1` | `yanuo.shell-classic` | 1 号快捷位指向的面板 id；空 = 不用这个键 |
| `quick2` | 空 | 2 号快捷位 |
| `limit` | 8 | 同时显示的面板数，4–12 |
| `recenter` | `away` | 显示面板时的摆放：`never` / `away` / `always` |
| `blockInput` | `true` | 指着或抓着面板时挡住游戏按键 |
| `grabDelay` | `0.15` | 抓取延迟(秒)：`0` / `0.15` / `0.4` |
| `stretch` | `true` | 双手缩放 |
| `snap` | `true` | 松手时摆正 |
| `hitTest` | `js` | 指针落点的算法：`js` / `native` |
| `hitCheck` | `false` | 两种算法各算一次，差 2 像素以上记日志 |
| `textureSubmit` | `always` | 画面交给 SteamVR 的方式：`always` 每个显示帧都交 / `changed` 画面变了才交 |
| `attach` | `native` | 附着的面板怎么跟着设备：`native` 交给 SteamVR 带着走 / `js` 每帧自己算位置 |

前八项由共用的 `readSettings` 收窄(坏的值用默认值)，也出现在远程服务 `panels` 的状态里(`options`、`limit`、每块面板的 `quick`)；后四项是排查用的，只有这个组件读。

## 远程服务 panels

约定见 [SDK](sdk.md#显示方ctxpanels-和远程服务-panels)。这个组件的实现：

| | 行为 |
|---|---|
| 状态 | 目录里的面板都列出来；`connected` 是连没连上 SteamVR；每块的 `open`、`visible`、`pinned`、`locked`、`anchor`、`glance`、`meters`(实际宽度)、`quick`、`error` 照布局和设置给出。`visible` 是按布局算的「这一刻该显示」，悬浮窗口一帧建一个时会晚几帧跟上；附着的面板设备不在、抬手才显示的没朝向眼睛时是假；没连上时都是假 |
| `open(id, on)` | 打开或关掉一块面板 |
| `toggleAll()` | 和总开关键一样：有面板藏着(被收起着，或关着)就全部显示，否则整组收起 |
| `summon(id?)` | 打开这块面板并重新放到面前；不写 id = 显示着的面板都重新放。附着的面板照样打开，位置不动 |
| `reset(id)` | 附着在哪、抬手才显示、宽度回到清单的值，位置回到默认(留在空间里的放到面前，附着的回到设备上的默认位置)，锁定照清单的附着对象(在手上的锁着，别的不锁)；常显不动 |
| `set(id, patch)` | 改常显、锁定、宽度、附着在哪、抬手才显示。换附着对象时位置回到新对象的默认位置；换到手上时连带抬手才显示、锁上、比 0.3 米宽的缩到 0.3 米(不小于清单的最小宽度)，同一次调用里给了的项照给的 |
| `lockAll(on)` | 全局锁 |

参数不对的调用、目录里没有的面板不做任何事。快捷位没有对应的远程调用，只有手柄键。

## 模拟模式

带环境变量 `FOXPANEL_VR_SIM=<脚本.json>` 启动时，组件不连 SteamVR：用不碰原生库的 `FakeVr` 加真的 D3D 设备跑脚本。离屏页面 → 句柄复制 → D3D 打开和复制 → 指点回页面这一整段和真的一样，不用头显就能看到结果。脚本只跑一遍，跑完照常连着。

脚本(JSON)：

```json
{
  "out": "sim-out",
  "hz": 90,
  "end": 16000,
  "steps": [
    { "at": 3000, "hand": "right", "press": "toggle", "down": true },
    { "at": 3100, "hand": "right", "press": "toggle", "down": false },
    { "at": 13000, "hand": "right", "panel": "yanuo.shell-classic", "aim": [0.5, 0.5] },
    { "at": 13500, "hand": "right", "press": "click", "down": true },
    { "at": 13600, "hand": "right", "press": "click", "down": false },
    { "at": 14000, "hand": "left", "panel": "yanuo.panel-clock", "aim": [0.5, 0.5] },
    { "at": 14500, "hand": "left", "press": "grab", "down": true },
    { "at": 14600, "hand": "left", "move": [0.3, 0, 0] },
    { "at": 15500, "hand": "left", "press": "grab", "down": false }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `out` | 结果放在哪个文件夹；相对路径相对脚本所在的文件夹，不写就是脚本所在的文件夹 |
| `hz` | 头显刷新率，1–1000，默认 90 |
| `end` | 连上之后多少毫秒算跑完，不小于最后一步的 `at` |
| `steps` | 按 `at`(连上之后的毫秒数)从小到大，每步是下表里的一种 |

| 步骤 | 做什么 |
|---|---|
| `{ at, head: 12 个数 }` | 头的姿态 |
| `{ at, hand, pose: 12 个数 或 null }` | 一只手(手柄)的姿态；`null` = 姿态无效 |
| `{ at, hand, tip: 12 个数 }` | 这只手的指尖相对手柄的变换。组件在这只手的设备第一次出现时取指尖，所以写在 `at` 为 0 的那一步；没给的手指尖就在手柄上 |
| `{ at, hand, aim: [x, y], panel? }` | 这只手指着一块面板纹理上的一点(0–1，左上角为原点；按面板当时的姿态算出手的姿态，离面板 0.3 米)。跟着设备的悬浮窗口按那个设备这一刻的姿态算在哪；给过这只手的指尖时，手柄摆成让指尖在落点正前方。`panel` 是面板 id，不写 = 显示着的悬浮窗口里建得最早的那块 |
| `{ at, hand, move: [dx, dy, dz] }` | 这只手从当时的位置平移(米，站立空间) |
| `{ at, hand, press, down }` | 按下或松开一个键：`toggle`、`click`、`grab`、`quick1`、`quick2` |
| `{ at, panel, wheel: [dx, dy], point?: [x, y] }` | 不经手柄，直接往这块面板的页面发一次滚轮：落在纹理上的 `point`(0–1，默认正中)，滚动量是像素，`dy` 为正往下滚 |

`hand` 是 `left` 或 `right`。没给头的姿态时：站在原点、眼睛高 1.6 米、朝 −Z 看。`hitTest: native` 和 `hitCheck` 问到的求交按 SteamVR 的规则算(命中区域是以悬浮窗口的原点为中心、边长等于宽度的正方形)。指不着(面板没显示、它跟着的设备不在)、没有手可挪、面板没开过页面的步骤各记一行警告。

跑完在 `out` 里写结果，运行日志里记一行 `vr sim finished: <文件夹>`：

| 文件 | 内容 |
|---|---|
| `<面板 id>.png` | 每块有画面的面板一张：它的常驻纹理读回来的画面 |
| `result.json` | `{ panels: [...] }`，开过页面的面板按开的先后各一项：`id`、`image`(画面的路径，没有画面时是 `null`)、`texture`(常驻纹理的宽高)、`overlay`(悬浮窗口显示没有、宽度 `meters`、最后一次放它时给的矩阵 `pose`、那一次相对哪个设备 `device`——设备序号，`null` = 站立空间里的绝对位置；没建或已经销毁时整项是 `null`)、`shows`(悬浮窗口每次显示和隐藏：`{ at, on }`，`at` 是连上之后的毫秒数)、`inputs`(发给页面的指点事件，带发出的时间；连着几次一样的移动只记一次) |

`npm run smoke` 的离屏方式那一段用的就是它(见 [打包和更新](release.md#冒烟检查))。
