# 输入法

输入法和键盘的整条流程(按键怎么变成字、输入框、候选、语言和模式、发送、自动送出、PIN、听写)都在预装的服务组件 `components/ime`(id `yanuo.ime`)里。核心没有输入法，也没有键盘专属的代码：键盘的状态和操作走通用的远程服务通道。这篇讲这个组件的结构、语言组件怎么接进来、每种按键怎么处理。语言组件清单的写法见 [组件格式](components.md)，键盘面板怎么显示状态见 [面板页面](panel-page.md#键盘面板)。

## 结构

清单：`kind: service`，`provides: ["keyboard"]`，`"process": "own"`(主进程代码单独一个组件进程，见 [组件进程](component-process.md))，入口有 `main`(组件进程)、`page`(键盘面板的页面里提供 `kb` 服务、盖部署提示)和 `window`(主窗口里的一小部分)。它的页面部分用自己提供的远程服务 `keyboard`，清单不用为此写 `uses`：页面部分只在有部件 `requires` 了 `keyboard` 的面板里加载，那一页已经够得着它(见 [组件格式](components.md#服务))。

```
键盘上的部件 ── ctx.kb.act ──▶ 页面部分 page.ts ── tell('act') ──▶ 核心的远程服务通道 ──▶ served.ts 收窄 ──▶ 键盘服务 keyboard.ts
听写等主进程组件 ───────── ctx.relay.use('keyboard').tell(…) ──▶ 同一条通道                    ├─ rime 工作线程 worker.ts
                                                                                                    ├─ 韩文拼字 korean.ts
                                                                                                    ├─ 输入框 text.ts
                                                                                                    └─ 发送 outbox.ts ── ctx.output.send ──▶ 核心 ──▶ 输出组件
键盘服务 ── publish(状态) ──▶ 核心的远程服务通道 ──▶ 订阅了 keyboard 的页面和组件进程
```

`components/ime/src/` 里的文件：

| 文件 | 内容 |
|---|---|
| `main.ts` | 入口：各个路径、rime 补丁文件、语言同步、键盘设置的存取、登记成远程服务 `keyboard` 的提供方、读应用信息、和主窗口部分的总线 |
| `served.ts` | 远程服务 `keyboard` 收到的调用：参数收窄后交给键盘服务，听写结果看调用者 |
| `page.ts`、`empty.ts` | 页面部分：在键盘面板的页面里提供 `kb` 服务；没有状态时用的空状态 |
| `veil.ts`、`words.ts` | 页面部分的部署提示(弹层)和它的文字(五种界面语言) |
| `keyboard.ts` | 键盘服务 `KeyboardService`：按键处理、语言和模式、听写、搜狗导入、操作队列 |
| `outbox.ts` | 发送、自动送出、PIN、「正在输入」、翻译 |
| `text.ts` | 输入框文字 `TextBuffer`：内容、光标、选区 |
| `keys.ts` | 键位 → 字符(标准美式键盘的平时 / Shift 两个字符) |
| `actions.ts` | 把收到的操作收窄成 `KeyboardAction` |
| `settings.ts` | 键盘设置的默认值和校验 |
| `imepack.ts` | 清单 `ime` 字段的校验，当前语言和模式 |
| `langs.ts` | 语言组件的 rime 文件同步进用户目录 |
| `client.ts`、`worker.ts`、`protocol.ts`、`rime.ts`、`koffi.ts` | rime 工作线程：调用端、线程入口、消息、librime 绑定 |
| `hangul.ts`、`korean.ts`、`hanja.ts` | 韩文两套式拼字、韩文输入、韩文汉字词库 |
| `sogou.ts` | 搜狗用户词库的解析 |
| `window.ts`、`LangSection.vue`、`state.ts`、`channels.ts`、`locales.ts`、`i18n.ts` | 主窗口部分和它用的总线频道、文案 |

## 远程服务 keyboard

组件用 `ctx.relay.serve('keyboard', …)` 登记成远程服务 `keyboard` 的提供方(`main.ts`)。约定的类型(`KeyboardState`、`KeyboardCalls`、`KeyboardAction` 等)在 `sdk/keyboard.ts`。核心只管通道，不看内容(见 [组件进程](component-process.md#远程服务))。

- **状态**：键盘服务每次有变化就把整份输入状态(`KeyboardState`)用 `publish` 发布，核心只发给订阅了 `keyboard` 的页面和组件进程。组件关着或它的进程没在跑时，使用方读到的状态是 `null`。
- **收到的调用**(`served.ts`，参数都按 `unknown` 收)：

| 方法 | 内容 |
|---|---|
| `act(操作)` | 按键等操作。`actions.ts` 收窄各字段，格式不对的丢掉 |
| `insert(文字)` | 在光标处插入；不是字符串的丢掉 |
| `dictated(文字, final)` | 听写结果。只收调用者是主进程组件、并且是应用信息里接了听写的输入源(`AppInfo.inputs`)发的，页面和别的组件发的丢掉 |
| `dictationEnded()` | 听写在别处停了。调用者的限制同上 |

- **页面部分**(`page.ts`，插件写 `inject: ['overlay', 'i18n']`)：在键盘面板的页面里 `ctx.relay.use('keyboard')`，把它包成 `kb` 服务给键盘上的部件用(`ctx.provide('kb', …)`)。状态的 `ready` 为假(远程状态为 `null`，或 rime 在部署)期间用弹层盖住整页，显示「输入法部署中…」(`veil.ts`；文字跟界面语言，点空白处不关，盖着时点不到下面的键)。`kb.state` 始终是同一个响应式对象，远程状态为 `null` 时内容是空状态(`empty.ts`：`ready` 为假、没有语言)，有状态时只给换了值的字段赋值；`act`、`setOutput` 用不等结果的 `tell`，同一页发的按先后送到；每次状态到了发 `kb/change`，`page(dir)` 发 `kb/page`。

组件要核心做的事走通用的接口，不经远程服务：

| 接口 | 内容 |
|---|---|
| `ctx.app.info`、`ctx.app.watch` | 界面语言、装着的输出组件(开关、收不收实时内容、能不能显示「正在输入」)、有没有输入源接了听写、语言组件(装着的每个的文件夹和清单、在用的顺序)。键盘用到的这几项变了才跟上 |
| `ctx.output.send` / `typing` / `clear` | 发给开着的输出、「正在输入」、清除各输出显示的内容 |
| `ctx.app.setOn` | 开关一个输出组件 |
| `ctx.input.dictate`、`ctx.translator.translate`、`ctx.app.clipboard` | 开关听写、翻译一句、读写系统剪贴板 |

| 位置 | 内容 |
|---|---|
| 程序目录 `vendor/rime/rime.dll` | librime |
| 程序目录 `vendor/rime/data/` | 内置的方案和词库(rime 的共享数据目录)：四叶草拼音 `clover`、英文 `easy_en`、日语 `jaroomaji`、OpenCC 等 |
| 程序目录 `vendor/rime/hanja.txt` | 韩文汉字词库 |
| 数据文件夹 `rime/data/` | rime 用户目录：语言组件的方案文件、程序写的补丁、用户词 |
| 数据文件夹 `rime/build/`、`rime/prebuilt/`、`rime/log/` | 部署产物、预编译数据目录、rime 的日志(只记错误) |
| 数据文件夹 `rime/lang-files.json` | 各语言组件放进用户目录的文件清单 |

`vendor/rime` 由 `npm run vendor:rime` 下载(见 [打包和更新](release.md))。没有 `rime.dll` 时往运行日志记 `missing vendor/rime, run npm run vendor:rime`，rime 不启动。

组件往 rime 用户目录写这几个文件：三个方案补丁在组件启动时写，`default.custom.yaml` 在每次同步语言组件时写(见「语言组件」)。内容没变就不碰文件(rime 部署时按配置文件的修改时间决定方案要不要重新编译)：

| 文件 | 内容 |
|---|---|
| `default.custom.yaml` | `schema_list`：全部已装且能用的语言用到的方案 |
| `clover.custom.yaml` | 关掉 emoji 联想和符号 |
| `jaroomaji.custom.yaml` | 默认用日文模式 |
| `easy_en.custom.yaml` | 过滤器只留 `uniquifier` |

## rime 工作线程

rime 跑在组件进程里的一个工作线程(`worker.ts`)，独占 librime 和一个会话；部署会阻塞数秒，放在线程里不卡组件进程。

- 绑定(`rime.ts`)：用 koffi 调 librime 1.17 的 C 接口；用户词库的导入经 `levers` 模块。koffi 用程序自带的那一份，主线程把模块地址传给工作线程。
- 调用端(`client.ts`)把请求排成一队，前一个完成或失败后才发下一个。线程出错或退出后，在等的和之后的请求都以失败结束。
- 每个请求的回复是这次上屏的文字、输入串和其中的光标、候选。候选一次最多取前 200 个(单个字母有几千个候选)，每个候选带它在全部候选里的序号。

请求的种类(`protocol.ts`)：

| kind | 做什么 |
|---|---|
| `init` | 初始化 librime、部署、开会话，选方案和开关 |
| `schema` | 选方案并设开关；方案没变时只设开关，不打断输入 |
| `deploy` | 重新部署：关掉会话、检查全部方案、开新会话、选回方案和开关 |
| `key` | 一个键，名字是 keysym 名(`a`、`space`、`BackSpace`、`Return` 等) |
| `char` | 一个可打印的 ASCII 字符；回复里带 rime 有没有处理它 |
| `select` | 选候选 |
| `raw` | 取出按下的原始字母并结束输入 |
| `clear` | 丢弃输入 |
| `importDict` | 导入用户词库，回复条数(失败为 -1) |

## 启动和部署

引擎有四个状态：没启动、部署中、能用、初始化失败。输入状态里的 `ready` 只在「能用」时为真，为假时输入法的页面部分在键盘面板上盖着部署中的提示。

- 组件加载时按应用信息里的语言列表启动：初始化 rime 并部署词库，首次较慢。开始部署时发布一次没就绪的状态(语言包、界面语言、键盘设置已经有了)，部署完发布就绪的状态。初始化失败后 rime 一直不能用；韩文和直接打字母的模式不经过 rime，照常能打。
- 语言组件装上、卸载或文件有变，使 rime 用户目录变了：丢弃没打完的输入，进入部署中，重新部署后回到能用。
- 语言的开关、顺序、界面语言、输出组件变了：只重新定当前语言，把新状态发出去。

键盘服务里有两条队列：

- 操作队列：会改输入状态的入口(操作、改模式、听写结果、搜狗导入等)依次执行。一个键要等 rime 回复才有结果，下一个键在那之后才处理。
- 部署队列：初始化和重新部署一个个来。等 rime 部署的时候不占操作队列，按键照常处理，用到 rime 的不生效。

## 语言组件

语言是 `kind: lang` 的组件，清单的 `ime` 字段和 `rime/` 文件夹的写法见 [组件格式](components.md)。核心不看这些内容；输入法组件从应用信息(`ctx.app.info.components`)里读已装的语言组件(目录和清单)和在用的顺序。

已装的语言组件(开没开都算)有变时，`langs.ts` 把它们对上 rime 用户目录：

1. 校验 `ime` 字段(`imepack.ts` 的 `parseIme`)，补上默认值：`short` 取名字的第一个字，`lang` 为 `und`，没写 `modes` 时是一个叫 `default` 的模式，`engine` 为 `hangul` 又没写 `keycaps` 时用两套式的键位。
2. 检查文件：用到的每个方案，`<方案>.schema.yaml` 要在组件的 `rime/` 或内置数据里；`rime/` 里的文件不能和程序自己的文件(上表四个，加 `default.yaml`、`installation.yaml`、`user.yaml`)、内置数据里的文件、别的语言的文件同名(不分大小写)；`rime/` 里不能有链接。
3. 没通过的语言跳过，运行日志里记 `<id> skipped: 原因`。
4. 通过的语言：`rime/` 里新的、内容变了的文件复制进用户目录，文件清单记进 `rime/lang-files.json`；清单里有、已装语言里没有的文件删掉，空出来的文件夹一起删。
5. 写 `schema_list`。
6. 用户目录有变就重新部署。

开着的语言按组件顺序成为输入状态里的 `packs`；开关和顺序不用重新部署。

当前语言和模式：

- 存在键盘设置的 `lang` 和 `modes`(各语言当前的模式)里。当前语言没装或关掉了，用第一个开着的；一种都没开时用内置的「ABC」，直接打字母。模式没存过或不认识时用第一个。
- `lang` 操作切换语言，可以同时指定模式；只能切到开着的语言。换了语言时丢弃没打完的输入。
- 语言和模式决定按键走哪条路：

| 情况 | 处理 |
|---|---|
| `engine` 为 `hangul` | 韩文拼字 |
| 模式写了 `direct` | 直接插入字符 |
| 其余 | 交给 rime：方案用模式的 `schema`，没写用语言的；选方案后设模式的 `switches` |
| 模式写了 `output` | 交给 rime，但不出候选，上屏的是输入串(假名) |

预装的四种语言：

| 组件 | 方案 | 模式 |
|---|---|---|
| `components/lang-zh` 拼音 | `clover` | 简体、繁体(开关 `zh_simp_s2t`) |
| `components/lang-en` English | `easy_en`，`latin` | 单词、字母(`direct`) |
| `components/lang-ja` ローマ字 | `jaroomaji`，`enter: rime` | 漢字、ひらがな(`output: composition`)、カタカナ(`output: katakana`) |
| `components/lang-ko` 두벌식 | `engine: hangul` | 한글、한자(模式 id `hanja`) |

自带方案文件的示例在 `examples/lang-xiaohe/`(小鹤双拼，词库用内置的四叶草拼音)。

## 按键处理

`key` 操作带键位 `code` 和 `shift`。`keys.ts` 按标准美式键盘把键位换成字符：字母、空格、数字和符号是可打字的键，其余是编辑键。

Tab 在哪种语言下都一样：输入中的内容先上屏，再插入四个空格。

直接打字母的模式下，可打字的键直接插入字符。不在输入中(没有输入串)时，编辑键作用在输入框上；直接打字母的模式没有输入串，一直是这样：

| 键 | 作用 |
|---|---|
| Backspace / Delete | 有选区时删选区，否则删前 / 后一个字素 |
| 输入框空着时的 Backspace、←、→、↑、↓ | 往总线发 `yanuo.ime/idle-key`，别的组件据此在它那边删字、移动。按住退格从有字删到空就不再发，松开再按才发。是不是按住连发的看操作的 `repeat`：页面部分在同一次按下里再来的退格、方向键上标 `repeat: true` |
| Enter | 发送 |
| ← / → | 移动一个字素；有选区时收到选区对应的一端 |
| ↑、Home / ↓ | 光标到开头 / 末尾 |

当前语言用 rime 方案时：

| 键 | 不在输入中 | 输入中 |
|---|---|---|
| 小写字母 | 交给 rime，开始输入 | 交给 rime |
| 大写字母 | 直接插入 | 输入中的内容上屏，再插入 |
| 数字 | 直接插入 | 选第几个候选(1–9 是前九个，0 是第十个)；有候选但没有这一个时不动；没有候选(假名模式)时输入串上屏，再插入数字 |
| 空格 | 插入空格 | 上屏第一个候选 |
| 符号 | 交给 rime，方案不处理的原样插入 | 同左；假名模式下先把假名上屏 |
| Enter | 发送 | 语言的 `enter` 为 `raw` 时上屏按下的字母，为 `rime` 时交给方案；假名模式上屏输入串 |
| Backspace、Delete、←、→ | 作用在输入框上 | 交给 rime |
| ↑、Home / ↓ | 光标到开头 / 末尾 | 输入串里的光标到开头 / 末尾 |

- 「上屏第一个候选」是向 rime 按空格：第一次上屏第一个候选，之后每次上屏一段没有候选的输入，直到又出现候选或输入结束，最多按 8 次。
- 拼音文字(语言写了 `latin`)：字母连同大写都进输入串；空格、数字、符号先把单词上屏，再原样插入。
- 假名模式：候选列表是空的；片假名模式把输入串和上屏文字里的平假名换成片假名。
- 含 emoji 的候选不放进候选列表(VRChat 聊天框显示不了)。

其他和输入有关的操作：

| 操作 | 处理 |
|---|---|
| `text` | 输入中的内容先上屏，再把文字插到光标处 |
| `select` | 选候选：rime 的按全部候选里的序号，韩文的按候选列表里的位置 |
| `caret` / `range` | 放光标 / 选中一段；落在字素中间的位置对齐到它前面的边界 |
| `paste` | 读系统剪贴板，换行换成空格，插到光标处 |
| `copy` | 有选区时复制选区，否则复制全部文字 |
| `clear` | 清空输入框，丢弃没打完的输入 |

输入框(`text.ts`)的位置都是 UTF-16 位置；删除和移动按完整的字素，不会把 emoji 或组合字符分成两半；插入时有选区就替换选区。

## 韩文拼字

`engine` 为 `hangul` 的语言不经过 rime，由组件自己拼字。

`hangul.ts` 是两套式(두벌식)：QWERTY 字母键对应韩文字母，Shift 时有双辅音或 ㅒ、ㅖ 的用它们；字母按初声、中声、终声拼成音节，支持 7 种复合元音和 11 种双收音；收音后面接元音时，收音成为下一个音节的初声(双收音只带走后一半)；退格按键入的顺序一个字母一个字母地退。

韩文语言下的按键：

| 键 | 作用 |
|---|---|
| 字母 | 拼字。在拼的音节是输入串；韩文模式下拼完的音节直接上屏 |
| 数字 | 有候选时选第几个候选，否则和空格、符号一样 |
| 空格、符号 | 输入串上屏，再插入这个字符 |
| Backspace | 退一个字母；汉字模式下没有在拼的音节时退一个音节；没有输入串时删输入框里的字 |
| Enter | 输入中：上屏输入串；否则发送 |
| 其余编辑键 | 输入串先上屏，再作用在输入框上 |

汉字模式(模式 id 为 `hanja`，`korean.ts`)：拼好的音节留在输入串里连成一个词，候选是它的汉字写法，来自 `vendor/rime/hanja.txt`(每行「韩文:汉字:释义」)。整个词对得上的排在前面，只换最后一个字的排在后面，最多 60 个；选整词的候选替换整个输入串，选单字的只替换最后一个字。词库有几兆，切到汉字模式时提前读入，还没读完就要查时当场读。

## 发送、自动送出、PIN

`outbox.ts`。输出组件分两种：只收发送的，和也收实时内容的(注册时写了 `live`，见 [SDK](sdk.md))。

| 功能 | 规则 |
|---|---|
| 发送 | `send` 操作，或不在输入中时按 Enter。输入中的内容先上屏；输入框的文字交给开着的输出组件，带提示音；空文字也发(表示清空显示)。发完清空输入框；开着 PIN 时文字留在输入框里 |
| 自动送出(`autoSend`) | 输入框的文字每变一次重新计时，停下 1500 毫秒后发给收实时内容的输出，带提示音。和上一次自动送出的是同一句时不发；输入框空了以后这条记录清掉 |
| PIN(`pinMessage`) | 打开时马上发一次，之后每 2000 毫秒把输入框的文字重发给收实时内容的输出，不带提示音。输入框只有空白或没有收实时内容的输出时不发 |
| 「正在输入」(`showTyping`) | 开着且有开着的输出能显示它时：每次打字(按键、插入文字、听写出字)通知一次，最后一次打字 6000 毫秒后撤掉；设置关掉时马上撤掉 |
| 翻译 | 发出之前，去掉首尾空白的文字先用 `ctx.translator.translate` 交给翻译组件。输出组件拿到原文 `text` 和译文 `spoken`；没有翻译组件时两者相同。出错或超过 15 秒时用原文，往运行日志记 `translate failed: …`，同一句只试一次。空文字不翻译 |

自动送出和 PIN 的文字在翻译回来时如果输入框已经变了，这一次不发。

`clearOutputs` 操作让各输出清掉显示的内容(聊天气泡)；`output` 操作开关一个输出组件：组件调 `ctx.app.setOn`，由核心改组件的开关；核心只开关装着的输出组件，别的 id 不处理。聊天框输出见 [OSC 服务](osc.md)，语音合成见 [语音合成、听写、翻译](voice.md)。

## 听写

- `dictate` 操作开 / 关听写；没有输入源接了听写时开不了。组件调 `ctx.input.dictate`，核心把开关交给组件顺序最前的那个输入源。
- 听写结果(远程服务的 `dictated`)只收接了听写的输入源组件发的，并且只在听写中才收：没说完的半句放进输入状态的 `dictation`，只显示在光标处；说完的一句去掉首尾空白后插到光标处。
- 输入源那边自己停了(麦克风或识别断开)时，输入状态的 `dictating` 跟着变成假。

输入源组件怎么采集和识别见 [语音合成、听写、翻译](voice.md)。

## 键盘设置

键盘设置存在组件自己的数据里(键 `settings`)，随输入状态的 `settings` 发给各处；`settings` 操作带一个补丁来改，补丁里格式不对的项被忽略(`settings.ts`)。

| 键 | 默认 | 说明 |
|---|---|---|
| `showTyping` | `true` | 打字时让输出显示「正在输入」 |
| `autoSend` | `false` | 自动送出 |
| `pinMessage` | `false` | PIN |
| `lang` | `yanuo.lang-zh` | 当前语言(语言组件 id) |
| `modes` | `{}` | 各语言当前的模式(语言组件 id → 模式 id) |

键盘面板的宽度、挡不挡游戏按键、显示时放不放回面前不是键盘设置：宽度在显示方的布局里(用双手缩放改，范围是经典外壳清单的 0.4–1.6 米)，后两样是 SteamVR 组件的设置(见 [SteamVR 悬浮面板](steamvr.md#布局和设置))。深色也不是键盘设置：它是全部面板共用的外观，存在核心设置的 `panels.dark`，日夜切换按钮经 `ctx.panel.setDark` 改(见 [面板页面](panel-page.md#计划和外观))。

## 主窗口部分

`window.ts` 跑在主窗口里，往组件详情的插槽 `component-details` 放一节「基础设置」(`LangSection.vue`，顺序 -50)。只有语言组件的详情里才出现：

- 模式多于一个的语言：一个「模式」下拉，选了立即生效。
- 方案是 `clover` 的语言(预装的拼音)：「搜狗词库」一行和导入按钮，说明处显示已导入的条数或失败原因。

两样都没有的语言不显示这一节。主窗口部分和组件进程里的部分用总线通信(`channels.ts`，收到的数据都先收窄)：

| 频道 | 方向 | 数据 |
|---|---|---|
| `yanuo.ime/get` | 主窗口 → 组件进程 | 要一份语言信息 |
| `yanuo.ime/langs` | 组件进程 → 主窗口 | 全部能用的语言(id、是不是拼音、各模式的 id 和名字)、各语言当前的模式、已导入的搜狗词条数；有变就发 |
| `yanuo.ime/mode` | 主窗口 → 组件进程 | `{ id: 语言组件 id, mode: 模式 id }` |
| `yanuo.ime/sogou` | 主窗口 → 组件进程 | 导入搜狗词库 |
| `yanuo.ime/sogou-done` | 组件进程 → 主窗口 | `{ ok: true, count }` 或 `{ ok: false, error }` |
| `yanuo.ime/idle-key` | 组件进程 → 别的组件 | `{ key, repeat }`(SDK 的 `IdleKeyNotice`)：输入框空着时按了 `Backspace`、`ArrowLeft`、`ArrowRight`、`ArrowUp`、`ArrowDown`，`repeat` = 按住连发的。频道名和数据的收窄(`IDLE_KEY`、`parseIdleKey`)在 `components/_shared/keyboard.ts` |

### 搜狗词库导入

把本机搜狗拼音的用户词库导入四叶草拼音的 rime 用户词库(`sogou.ts`、`keyboard.ts` 的 `importSogou`)：

1. 在 `%USERPROFILE%\AppData\LocalLow\SogouPY.users\` 的各个子文件夹里找 `sgim_gd_usr.bin`，用最近修改的那个。
2. 解析词库(文件头是 `SGPU`)，读出词、拼音和使用次数。只留纯汉字、不超过 8 个字、每个字都有拼音的词；同一个词同样的拼音，次数相加。
3. 转成 rime 的导入文本(每行「词、拼音、次数」，用制表符隔开，次数至少为 1)，写成 `rime/build/sogou_import.txt`，用完删掉。
4. 工作线程经 `levers` 模块导入 `clover` 的用户词库。导入前关掉会话(会话开着词库时写不进去)，导入后开新会话并选回方案和开关；没打完的输入串在导入前丢弃。
5. 条数存进组件数据的 `sogouWords`，结果发回主窗口。

rime 还没就绪、找不到搜狗用户词库、rime 导入失败时，返回带原因的失败结果，不改已有的条数。
